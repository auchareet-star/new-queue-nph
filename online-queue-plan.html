แผนคิวออนไลน์ HA.OS

หน้าจองคิว Walk-in ใน HA.OS ที่ดูคู่กับ Dashboard นัด/Walk-in รายคลินิก และออกบัตร V/P/N ได้จากหน้าเดียว พร้อมบริการออนไลน์ 3 อย่างให้คนไข้ทำจากมือถือ ได้แก่ ทำบัตร เช็กอิน และขอนัด ข้อมูลที่คนไข้ส่งเข้ามาจะพักไว้ก่อน แล้วให้เจ้าหน้าที่เป็นคนตัดสิน

ฉบับที่ 23 · 21 ต.ค. 2569 (บัตร Walk-in V/P/N ไม่จองเลขคิว · หน้าสรุปจุดบริการตั้ง Limit Walk-in · ตู้ Kiosk เฉพาะนัด · เช็กอินแบบพระนั่งเกล้า + ธงที่คัดกรอง · แจ้งผลทางหมอพร้อมอย่างเดียว · หน้านัดหมายใช้หน้าเดิม)อ้างอิง: เอกสารดูงานระบบคิว รพ.พระนั่งเกล้า, สเปก Limit ห้องตรวจ (14 ต.ค. 69) และโค้ด HA.OS สาขา developต้นแบบที่กดได้: online-queue-prototype.html ในโฟลเดอร์เดียวกัน

เรื่องตกลงว่า
จองคิว Walk-inเป็นหน้าใน HA.OS ไม่ใช่หน้าคนไข้ ดูคู่กับ Dashboard ที่บอกว่าแต่ละคลินิกมีนัดและ Walk-in เท่าไร และออกบัตร V/P/N ได้จากหน้าเดียวกัน
ใครออกบัตร / ใครเปิด Visitคนละคนกัน เจ้าหน้าที่จุดออกบัตรใช้หน้าจองคิว Walk-in แค่ออกบัตร แล้วคนไข้ถือบัตรไปยื่นที่เคาน์เตอร์เวชระเบียนเอง ไม่มีหน้าเรียกคิว ช่องเวชระเบียนใช้หน้าเดิมทั้งหมด ไม่ต้องแก้ ดูประเภทบัตรแล้วทำตามนี้ V = เปิด Visit · P = เวชระเบียนพิจารณาเปิด Visit หรือทำนัด · N = ลงทะเบียน HN ใหม่
อ่านบัตรที่จุดออกบัตรเสียบบัตร = ข้อมูลจากชิป (ชื่อ เลขบัตร วันเกิด ที่อยู่) + ตรวจสอบสิทธิได้ · ไม่ได้เสียบบัตร (ค้นด้วย HN/เลขบัตร) = ได้แค่ข้อมูลคนไข้จาก HA.OS ตรวจสิทธิไม่ได้ · ไม่มี HN และไม่ได้เสียบบัตร = ไม่มีชื่อ พิมพ์ได้แค่เลขบัตร
ชื่อบัตร V / P / Nตัวอักษรย่อจากสิ่งที่คนไข้ต้องทำต่อ: V = Visit ตรวจวันนี้ ไปเปิด Visit · P = Pending รอเวชระเบียนพิจารณา (คลินิกเต็ม มี HN) · N = Next นัดวันอื่น (คลินิกเต็ม ไม่มี HN ทำบัตรและนัด) · บนบัตรพิมพ์ทั้งตัวอักษรและคำไทย เพราะเครื่องพิมพ์บัตรเป็นขาวดำ · ไม่ใช้ A/R ซึ่งซ้ำกับรหัสในเลขคิวเดิมของ HA.OS
คิวด่วน / กลุ่มคิวเว้นไว้ก่อน ระบบเดิมมีอยู่แล้ว (ช่อง "ฉุกเฉิน?" ตอนเปิด Visit และบัตรคิวหลัง Visit) ไม่อยู่ในขอบเขตงานนี้
Dashboard มีคลินิกเยอะตั้งค่าชุดคลินิกที่แต่ละจุดออกบัตรดูแล (ตั้งครั้งเดียวต่อจุด/เครื่อง เหมือนการตั้งค่าตู้ Kiosk ไม่ผูกกับผู้ใช้ จึงไม่ต้องทำตารางผูกผู้ใช้กับคลินิก) + ช่องค้นหาที่ค้นได้ทุกคลินิก + ปุ่มกรองใกล้เต็ม/เต็ม + พับคลินิกย่อยใต้คลินิกหลัก เพราะ HA.OS ยังไม่มีการผูกผู้ใช้กับคลินิก
บัตร V ที่ยังไม่มี HNช่องเวชระเบียนลงทะเบียน HN ด้วยหน้าทะเบียนประวัติเดิม ตามปกติ แล้วเปิด Visit ด้วยหน้าเดิม
บัตร V / P / NV มี HN = คลินิกว่าง → ไปช่องเวชระเบียนเปิด Visit · V ไม่มี HN = คลินิกว่าง → ไปลงทะเบียน HN ใหม่แล้วเปิด Visit · P = เต็ม + มี HN → ให้เวชระเบียนพิจารณาเปิด Visit หรือทำนัด · N = เต็ม + ไม่มี HN → ไปลงทะเบียน HN ใหม่และทำนัด · ข้อความเหล่านี้พิมพ์อยู่บนบัตร
คลินิกหลัก / คลินิกย่อยนับแยกรายคลินิกย่อย เพราะตอนนัดก็นัดแยกได้ และดูรวมใต้คลินิกหลักได้ เพราะตอนเปิด Visit เลือกได้แค่คลินิกหลัก
บัตรคิวเก็บอะไรบ้างไม่จับคู่กับ Visit และไม่เก็บประวัติบัตร ระบบแค่ดูเงื่อนไข V/P/N ตอนออกบัตร แล้วพิมพ์บัตร เลขคิวจริงได้ตอนเปิด Visit และพิมพ์บัตรคิวเดิม (QueueCard) ตามปกติ · บัตรพิมพ์เวลาที่ต้องยื่นที่เวชระเบียน (ออกบัตร + 30 นาที ตั้งค่าได้) · ที่ว่าง = Limit Walk-in − Walk-in ที่เรียกเข้าห้องตรวจแล้ววันนี้ (อัปเดตเมื่อมีการเรียกคิวเข้าห้องตรวจนั้น)
ตู้ Kioskตู้ Kiosk เปิด Visit ได้เฉพาะนัดหมาย ปิดทาง Walk-in บนตู้ (ประเภทการเข้ารับบริการ Walk-in / เลือกห้องตรวจ) · คนที่ไม่มีนัดวันนี้ ตู้แจ้งให้ไปจุดออกบัตรคิว Walk-in · ทางนัดหมาย (AddVisitFormAppointment) ใช้เหมือนเดิม และไม่เกี่ยวกับเช็กอินออนไลน์ · ส่วนการดักคนที่มีนัดวันนี้ไม่ให้เปิด Walk-in ทำที่หน้าจองคิว Walk-in (จุดออกบัตร)
หน้าตั้ง Limit นัด / Walk-inใน HA.OS ยังไม่มี · ต้นแบบมีแล้ว (เคส C8): เมนูใหม่ "สรุปจุดบริการ" ตามสเปก Limit ห้องตรวจ ตั้ง Limit Walk-in ต่อจุด ตั้งครั้งเดียว เตือนไม่ล็อก · มีผลกับ Dashboard จุดออกบัตรทันที เพราะ Limit ระดับคลินิก = ผลรวมของจุดที่มีแพทย์วันนี้ ที่ว่างและการตัดสิน V/P/N จึงเปลี่ยนตาม · ต้องตัดสินใจเรื่อง Limit นัดของห้อง กับ LimitCase ของตารางแพทย์ ที่เป็นคนละตัวเลข (ดู Gap G-41) · ข้อเสนอ: Limit นัด = ผลรวม LimitCase ของตารางแพทย์วันนั้น ไม่ต้องตั้งเอง ตั้งเองแค่ Limit Walk-in
เช็กอินออนไลน์กรอกเฉพาะ Vital Sign ได้แก่ ความดัน ชีพจร อุณหภูมิ น้ำหนัก และส่วนสูง
ส่งลิงก์และแจ้งผลผ่านหมอพร้อมIT ของโรงพยาบาลเป็นคนจัดการ ฝั่ง HA.OS ส่งข้อมูลให้ IT · ไม่มีหน้าตรวจสถานะ ส่งทางหมอพร้อม: 1. ผลทำบัตร: ทำบัตรสำเร็จ (HN) / ใช้ HN เดิม / ปฏิเสธพร้อมเหตุผล 2. เตือนนัด + ลิงก์เช็กอิน · ผลคำขอนัดไม่ต้องส่ง ลงนัดแล้วเป็นนัดปกติ คนไข้ดูนัดในหมอพร้อมเอง (ถ้าปฏิเสธ เจ้าหน้าที่โทรแจ้ง) · ส่งตามเลขบัตรประชาชน (หมอพร้อมผูกกับเลขบัตร) คนไข้จึงไม่ต้องมี URL หรือเปิดหน้าค้างไว้ · ช่องทางเดียวคือหมอพร้อม ถ้าส่งไม่ถึง (เช่น คนไข้ยังไม่เคยใช้หมอพร้อม) หรือระหว่างที่ IT ยังไม่พร้อม เจ้าหน้าที่โทรแจ้งตามเบอร์ที่กรอก
หน้าหลักของ Mobile คิวไม่มีหน้าหลัก แต่ละหน้าเข้าจากลิงก์ของตัวเอง: ติดตามคิว = QR บนบัตรคิว (เดิม ไม่แตะ) · เช็กอิน = ลิงก์ในหมอพร้อม · ทำบัตร/ขอนัด = QR หรือลิงก์บนเว็บโรงพยาบาลและโปสเตอร์ (ทำบัตรเข้าหน้ากลางก่อน ให้เลือก ลงทะเบียนทำบัตรใหม่ / ตรวจสอบ HN) · ไม่มีหน้าตรวจสถานะ
ยืนยันตัวคนไข้บนหน้าออนไลน์ใช้เลขบัตรประชาชน + วันเกิด ส่วน OTP เว้นไว้ก่อน
คำขอนัดออนไลน์รับคำขอได้ไม่จำกัด คนไข้เลือกวันในสัปดาห์ที่มาได้ (จ.–อา. เลือกได้หลายวัน) ช่วงวันที่ หรือ "อื่น ๆ" แล้วเจ้าหน้าที่นำไปลงนัดในตารางที่ว่างของระบบนัดเดิม
ใครอนุมัติคำขอเจ้าหน้าที่ที่มีสิทธิ์เข้าเมนูนั้น ใช้ระบบสิทธิ์เมนูเดิม ระบบเก็บชื่อผู้กดและเวลาไว้ทุกครั้ง

งาน 1

จองคิว Walk-in (หน้าใน HA.OS ที่เวชระเบียน)

จองคิว Walk-in · คนที่ 1ช่องเวชระเบียน หน้าเดิม · คนที่ 2ใช้ Limit นัด/Walk-inรอ Limit ห้องตรวจ
ขนาด: ใหญ่
Vคลินิกว่าง · มี HNบนบัตร: ไปช่องเวชระเบียน เพื่อเปิด Visit
Vคลินิกว่าง · ไม่มี HNบนบัตร: ไปช่องเวชระเบียน เพื่อลงทะเบียน HN ใหม่ แล้วเปิด Visit
Pคลินิกเต็ม · มี HNบนบัตร: ไปช่องเวชระเบียน ให้เจ้าหน้าที่พิจารณาเปิด Visit หรือทำนัด
Nคลินิกเต็ม · ไม่มี HNบนบัตร: ไปช่องเวชระเบียน เพื่อลงทะเบียน HN ใหม่ และทำนัด

Flow

  1. คนไข้ Walk-in มาที่จุดออกบัตรหน้าเวชระเบียน ส่วนคนไข้นัดใช้ตู้ Kiosk ตามเดิม
  2. คนที่ 1 (จุดออกบัตร) เปิดหน้า จองคิว Walk-in ซึ่งแสดง Dashboard นัด/Walk-in ของวันนี้ เฉพาะชุดคลินิกที่จุดนี้ดูแล แยกคลินิกย่อย และมียอดรวมใต้คลินิกหลัก
  3. ขั้นแรก (อยู่บนสุดของหน้า) มี 2 ทาง: เสียบบัตร ได้ชื่อ เลขบัตร วันเกิด ที่อยู่จากชิป และตรวจสอบสิทธิได้ด้วยฟังก์ชันเดิม (ทั้งมีและไม่มี HN) · ไม่ได้นำบัตรมา พิมพ์ HN หรือเลขบัตร ได้แค่ข้อมูลคนไข้จาก HA.OS ตรวจสิทธิไม่ได้ และถ้าไม่พบ HN จะไม่มีชื่อให้พิมพ์ (ชื่อมาจากชิปเท่านั้น) · สิทธิที่ได้แสดงและพิมพ์บนบัตร ถ้าไม่ได้ตรวจ บัตรจะบอกให้ไปตรวจสิทธิที่เวชระเบียน · ถ้ามีนัดวันนี้ที่คลินิกหลักเดียวกัน ระบบดักไม่ให้ออกบัตร Walk-in
  4. เลือกคลินิก แล้วระบบเสนอประเภทบัตร เจ้าหน้าที่เปลี่ยนได้พร้อมใส่เหตุผล เช่น ผู้สูงอายุหรือกรณีเร่งด่วน
  5. กดออกบัตร ระบบพิมพ์บัตรที่บอกปลายทางตามประเภท (V มี/ไม่มี HN, P, N) โดยไม่เก็บประวัติบัตร คนที่ 1 ทำแค่นี้
  6. คนไข้ถือบัตรไปที่ช่องเวชระเบียนเอง ไม่มีการเรียกคิว
  7. คนที่ 2 (ช่องเวชระเบียน) ใช้หน้าเดิมทั้งหมด ไม่แก้ ดูประเภทบัตร: V = เปิด Visit (ยังไม่มี HN ก็ลงทะเบียนก่อน) · P = พิจารณาเปิด Visit หรือทำนัด · N = ลงทะเบียน HN ใหม่
  8. พอช่องเวชระเบียนเปิด Visit Walk-in ยอด "เปิด Visit" ของคลินิกเพิ่มขึ้นเองจากข้อมูลเดิม Dashboard จึงอัปเดตตาม

ตัวเลขสมมติ · ที่ว่าง = Walk-in Limit − เรียกเข้าห้องแล้ว · ตัวเลขชุดเดียวกับหน้าสรุปจุดบริการของฝั่งพยาบาล

ระบบตัดสินบัตรอย่างไร

ที่ว่าง = Σ Limit Walk-in ของจุดในคลินิก (เฉพาะจุดที่มีแพทย์ออกตรวจวันนี้) − Walk-in ที่เรียกเข้าห้องตรวจแล้ววันนี้ (นับตามจุดจากคิวห้องตรวจ ตามสเปก Limit · อัปเดตทุกครั้งที่เรียกคิวเข้าห้อง)
ที่ว่าง > 0 → V (แยกข้อความตามมี/ไม่มี HN) · เต็ม → P ถ้ามี HN / N ถ้าไม่มี HN · จุดที่ไม่ตั้ง Limit = ไม่จำกัด
ข้อแลกเปลี่ยนของการไม่เก็บประวัติบัตรระบบนับเมื่อเรียกคิวเข้าห้องตรวจแล้วเท่านั้น คนที่ได้บัตร V แล้วแต่ยังอยู่ระหว่างเปิด Visit หรือคัดกรอง (อาจ 1–2 ชั่วโมงในช่วงเช้า) ยังไม่ถูกนับ ระบบจึงยังเห็นว่าว่าง และอาจออกบัตร V เกิน Limit ได้มากกว่าการนับตอนเปิด Visit · ข้อดีคือยอดตรงกับหน้าสรุปจุดบริการ และรู้คลินิกย่อยได้จริงจากจุดที่เรียกเข้า · ซึ่งสอดคล้องกับหลัก "เตือน ไม่ล็อก" อยู่แล้ว เจ้าหน้าที่จุดออกบัตรดู Dashboard ประกอบ และเปลี่ยนเป็นบัตร P เองได้
2 ชั้นที่ทำงานต่อกันชั้นแรกคือหน้าจองคิว Walk-in ที่ตัดสินบัตรตามที่ว่างระดับคลินิก เพื่อกันคนล้นตั้งแต่หน้าโรงพยาบาล ชั้นที่สองคือ Limit ต่อจุด ตามสเปก 14 ต.ค. ที่นับตอนคัดกรองจัดคิวเข้าห้องตรวจ เพื่อกระจายคนไม่ให้ล้นรายห้อง

เงื่อนไขอื่น

  • P ที่เวชระเบียนตัดสินใจเปิด Visit ให้ เมื่อเรียกเข้าห้องตรวจจะนับเป็น Walk-in เกิน Limit และแสดงสีแดง ตรงกับหลัก "เตือน ไม่ล็อก" ของสเปก Limit
  • P/N ที่ทำนัดแล้ว จะนับเข้ายอดนัดของวันที่นัด ไม่ใช้ที่ว่าง Walk-in ของวันนี้
  • คนที่มีนัดวันนี้ ห้ามออกบัตร Walk-in ของคลินิกหลักเดียวกัน (ดักที่จุดออกบัตร) ให้เปิด Visit นัดตามปกติ
งาน 2

ลงทะเบียนทำบัตร (สร้าง HN) และให้เจ้าหน้าที่ยืนยัน

หน้าคนไข้คำขอทำบัตรออนไลน์ใช้ AddPatient
ขนาด: กลาง

Flow

  1. คนไข้เข้าจาก QR/ลิงก์ เจอหน้ากลางให้เลือก ลงทะเบียนทำบัตรใหม่ หรือ ตรวจสอบ HN (กรอกเลขบัตร + วันเกิด พบ = แสดง HN และชื่อแบบปิดบางส่วน ไปขอนัดต่อได้ · ไม่พบ = ไปลงทะเบียน)
  2. คนไข้ใหม่กรอกฟอร์ม และติ๊กยินยอม PDPA
  3. ระบบตรวจเลขบัตรซ้ำด้วย CheckDuplicateIdcardPatient ถ้ามี HN อยู่แล้ว แจ้งแค่ว่า "มีประวัติแล้ว" ไม่บอกข้อมูลอื่น
  4. เก็บเวลาที่ยินยอม PDPA ไว้กับคำขอ
  5. บันทึกลงตารางคำขอทำบัตร สถานะ "รอยืนยัน" และให้เลขอ้างอิง
  6. ห้องบัตรเข้าเมนูแล้วเจอหน้ารายการก่อน (แท็บรอยืนยัน / ดำเนินการแล้ว มีคอลัมน์ตรวจซ้ำ) กดเข้าหน้ารายละเอียด ซึ่งมีข้อมูลครบทุกช่องและแก้ได้ พร้อมกล่องตรวจซ้ำ 2 ชั้น: เลขบัตรประชาชน และ ชื่อ-สกุล + วันเกิด (จับประวัติเก่าที่ไม่ได้บันทึกเลขบัตร)
  7. เลือกได้ 3 ทาง: ยืนยันและออก HN ด้วย AddPatient · ใช้ HN เดิมและเติมเลขบัตร เมื่อพบประวัติเก่า · ปฏิเสธ พร้อมเหตุผล
  8. กดแล้วส่งแจ้งผลทันทีทางหมอพร้อมตามเลขบัตร (ส่งไม่ถึง = เจ้าหน้าที่โทรแจ้ง) (HN ใหม่ / HN เดิม / เหตุผลที่ปฏิเสธ + ให้นำบัตรประชาชนตัวจริงมาครั้งแรก) แล้วเก็บสถานะการส่ง · ไม่มีหน้าตรวจสถานะ

ช่องในฟอร์ม

คำนำหน้าเพศชื่อนามสกุลเลขบัตรประชาชนวันเกิดสัญชาติเบอร์มือถือบ้านเลขที่หมู่ตำบลอำเภอจังหวัดรหัสไปรษณีย์ผู้ติดต่อฉุกเฉิน: ชื่อความสัมพันธ์เบอร์ผู้ติดต่อยินยอม PDPAศาสนาอาชีพแพ้ยา (แจ้งเอง)

ฟอร์มของพระนั่งเกล้ามีช่องบังคับประมาณ 25 ช่อง ส่วน HA.OS บังคับแค่คำนำหน้า ชื่อ และนามสกุล จึงบังคับช่องที่ต้องใช้ระบุตัวตน ตรวจสิทธิ และติดต่อกลับ และแยกที่อยู่เป็นช่อง (จังหวัด/อำเภอ/ตำบลเลือกจาก Master) เพื่อให้ลงตารางผู้ป่วยได้ตรงรหัส

พักในตารางแยก ไม่ใช้ PreHnFlagFlagRegister = F จะเขียนลงตารางผู้ป่วยทันที ข้อมูลจากอินเทอร์เน็ตจึงควรพักในตารางแยกก่อน แล้วเรียก AddPatient เมื่อเจ้าหน้าที่ยืนยันแล้วเท่านั้น
งาน 3

เช็กอินออนไลน์สำหรับคนไข้นัด

หน้าคนไข้IT ต่อหมอพร้อมผูกตอนเปิด Visit นัด
ขนาด: กลาง

Flow

  1. ระบบสร้างโทเคนต่อนัด แบบเดียวกับ queuekey แล้วสร้าง URL ส่งให้ IT นำไปส่งต่อทางหมอพร้อม
  2. คนไข้กดปุ่มเช็กอินในหมอพร้อม แล้วหมอพร้อม Redirect มาเปิดฟอร์มของเรา หรือคนไข้เข้าเองด้วยเลขบัตร + วันเกิด
  3. หน้าแสดง HN ชื่อ วัน เวลา คลินิก แพทย์ และเหตุผลการนัด
  4. คนไข้ดูข้อมูลนัดและป้ายเหตุผลการนัด แล้วเลือก อาการปกติ / อาการผิดปกติ จากนั้นตอบแบบสอบถาม (ดูช่องในฟอร์ม) ถ้าตอบว่าไม่สะดวกเดินทาง มีปุ่มไปแจ้งเลื่อนนัด
  5. กด เช็กอิน → กล่องยืนยัน → หน้าเช็กอินสำเร็จพร้อมขั้นตอน (อาการผิดปกติ = ให้ติดต่อเคาน์เตอร์พยาบาล)
  6. บันทึกลงตารางข้อมูลเช็กอิน โดยยังไม่ผูกกับ Visit คนไข้แก้ได้จนกว่าจะเปิด Visit
  7. วันนัด คนไข้เปิด Visit นัดตามช่องทางเดิม (ตู้ Kiosk หรือเคาน์เตอร์) หน้าจอไม่แก้
  8. ใน AddVisitFormAppointment หลังเปิด Visit นัดสำเร็จ ถ้านัดนั้นมีข้อมูลเช็กอิน ระบบบันทึก Vital Sign เข้า Visit ทันที พร้อมอาการเป็น CC, สูบบุหรี่/สุราเป็นประวัติ และธงอาการผิดปกติ / แพ้ยาใหม่ (Vital Sign ใช้วิธีเดียวกับ VitalSignsPublicService.AddVitalSigns ที่เครื่องวัดใช้) โดยใช้วันเวลาที่คนไข้วัดเป็นเวลาวัด แล้วทำเครื่องหมายว่าผูกแล้ว · บันทึกไม่สำเร็จต้องไม่ทำให้เปิด Visit ล้ม
  9. หน้าคิวคัดกรองแก้เล็กน้อย: ป้าย "อาการผิดปกติ" / "แพ้ยาใหม่" ในแถวคิว และกล่องเตือนในหน้าซักประวัติ · แพ้ยาใหม่ไม่บันทึกลงรายการแพ้ยาเอง พยาบาล/เภสัชกรยืนยันก่อน · Vital Sign และ CC ขึ้นในช่องเดิม บันทึกทับได้

ช่องในฟอร์ม (ตามแบบพระนั่งเกล้า)

อาการปกติ / ผิดปกติอาการวันนี้สะดวกเดินทางไหมแพ้ยาใหม่ไหม (โชว์แพ้ยาเดิม)ความดัน SYS / DIAชีพจรน้ำหนักส่วนสูงอุณหภูมิวันที่ · เวลาที่วัดเบอร์โทร (ดึงเบอร์เดิม)สูบบุหรี่ดื่มสุรา
เงื่อนไขถ้าเลื่อนหรือยกเลิกนัด โทเคนต้องใช้ไม่ได้ · ค่าที่คนไข้วัดเองควรระบุแหล่งที่มาใน TB_VITAL_SIGNS (เช่น ผู้วัด) ไม่ปนกับค่าที่วัดที่ รพ. · กำหนดว่าวัดก่อนนัดได้ไม่เกินกี่ชั่วโมง · ต้องกำหนดว่าเปิดให้เช็กอินได้ตั้งแต่กี่วันก่อนนัด
ส่งให้ ITรูปแบบ URL, อายุของโทเคน, ข้อความบนปุ่ม และช่วงเวลาที่ควรส่ง เช่น 1 วันก่อนนัด
งาน 4

ขอนัดออนไลน์

หน้าคนไข้คำขอนัดออนไลน์ลงนัดด้วยระบบนัดเดิม
ขนาด: กลาง

Flow

  1. คนไข้ยืนยันตัวด้วยเลขบัตร + วันเกิด ถ้ายังไม่มี HN ให้ไปงาน 2 ก่อน
  2. คนไข้กรอกอาการ โรคประจำตัว คลินิก แพทย์ที่ต้องการ วันที่มาได้ รูปแนบ และเบอร์โทร
  3. บันทึกเป็นคำขอสถานะ "รออนุมัติ" โดยไม่จำกัดจำนวน แล้วให้เลขอ้างอิง
  4. เจ้าหน้าที่ที่มีสิทธิ์เมนู คำขอนัดออนไลน์ ดูอาการ รูป และวันที่มาได้ แล้วกด ลงนัด ระบบเปิดหน้าจอนัดเดิมพร้อมกรอกค่าไว้ และติดป้ายวันที่ตรงกับวันที่คนไข้มาได้ หรือกด ปฏิเสธ / โทรกลับ พร้อมเหตุผล
  5. คำขอเปลี่ยนเป็น "ลงนัดแล้ว" แล้วเก็บ AppointmentId ไว้ · ไม่มีหน้าแจ้งผลนัด นัดที่ลงเป็นนัดปกติของ HA.OS คนไข้ดูในหมอพร้อม · ถ้าปฏิเสธ เจ้าหน้าที่โทรแจ้งตามเบอร์ที่ให้ไว้ · คนไข้จะเข้า Flow เช็กอินออนไลน์ (งาน 3) ตามปกติ

ช่องในฟอร์ม

อาการ / เหตุผลคลินิก (หลัก/ย่อย)วันที่มาได้ จ.–อา. หรือ อื่น ๆเบอร์ติดต่อกลับช่วงวันที่ที่ต้องการโรคประจำตัวแพทย์ที่ต้องการรูปแนบ

เงื่อนไข

  • รับคำขอไม่จำกัด แต่มีตัวนับคำขอที่รอ และเวลาที่รอนานสุดบนเมนู
  • แจ้งเลื่อนนัด (ช่วงหลัง): เข้าจากข้อความเตือนนัดหรือหน้าเช็กอิน · เป็นคำขอประเภท "เลื่อนนัด" ผูกนัดเดิม ในเมนูเดียวกัน · เลื่อนแล้วโทเคนเช็กอินของนัดเดิมใช้ไม่ได้ และนัดใหม่ขึ้นในหมอพร้อม
  • คำขอที่เลยวันสุดท้ายของช่วงวันที่แล้วยังไม่มีใครลงนัด ให้เปลี่ยนเป็น "หมดอายุ" อัตโนมัติ ถ้าคนไข้เลือก "อื่น ๆ" ให้เจ้าหน้าที่ปิดเอง
  • ห้ามมีคำขอที่ยังรออยู่ซ้ำ คือเลขบัตรเดียวกันและคลินิกเดียวกัน
  • ลงนัดแล้วนับเข้า Limit นัด ของวันนั้น
